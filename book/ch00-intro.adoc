== 들어가며: 무엇을, 무엇으로 만드는가

이 책은 Java 진영의 데이터 액세스 기술을 아래에서 위로 쌓아 올리며 배우는 책이다.
JDBC 표준 API에서 출발해 Spring JDBC의 `JdbcTemplate`, 트랜잭션 추상화, Spring Boot의 자동 설정, Spring Data JDBC, 그리고 네이버가 공개한 확장 라이브러리 Spring JDBC Plus까지, 한 층을 이해한 뒤에 그 위층으로 올라간다.
아래층을 알고 위층을 쓰면, 위층이 감춰 주는 것이 무엇이고 무엇이 편해졌는지가 또렷하게 보인다.
반대로 위층만 알고 있으면 문제가 아래층에서 터졌을 때 손을 쓸 수 없다.

모든 장의 예제는 하나의 소재를 공유한다. 암기 카드 앱 *Flashcard*다.

=== 예제 앱: Flashcard

Flashcard는 이름 그대로 암기 카드 앱이다.
영어 단어·숙어·문장은 물론, 전공 용어처럼 짝을 이루는 지식이라면 무엇이든 카드로 만들어 암기할 수 있다.
카드의 두 면에는 원문과 뜻을 적고, 사용자는 카드를 뒤집어 답을 확인한 뒤 스스로 맞았는지 틀렸는지를 판정한다.

책의 마지막에 완성할 앱의 기능 요구사항은 다음과 같다.

* *학습 재료 만들기*: 덱(Deck)을 만들고 카드를 채운다. 카드에는 태그를 붙여 여러 덱에 흩어진 카드를 한데 묶는다. 스프레드시트에 정리해 둔 단어장을 CSV 파일로 한꺼번에 들여오고, 반대로 내보낼 수도 있다.
* *학습하기*: 학습 방향(원문→뜻, 뜻→원문)을 고르고, 카드를 뒤집고, 스스로 맞음/틀림을 판정한다. 덱을 한 바퀴 돌면 틀린 카드만 모아 재도전 라운드가 반복되므로, 세션이 끝나면 적어도 단기 기억에는 전부 들어가 있다.
* *꾸준히 복습하기*: 간격 반복(Spaced Repetition)으로 다음 복습 날짜를 앱이 대신 잡아 준다. 맞히면 복습 간격이 1일 → 6일 → 그 2.5배씩으로 늘어나고, 틀리면 1일로 돌아온다. 오늘 볼 카드는 홈 화면의 "오늘 복습" 큐에 자동으로 모인다. 재도전 라운드의 판정은 이 일정에 반영하지 않는다.
* *무엇을 공부할지 고르기*: 스마트 덱은 카드를 담아 두는 대신 "이런 카드를 모아 달라"는 조건만 적어 두는 덱이다. 자주 틀린 카드, 오래 안 본 카드, 특정 태그가 붙은 카드, 최근에 추가한 카드라는 네 가지 조건을 지원한다.
* *성취 확인*: 일별 학습량, 정답률, 연속 학습일(streak), 덱별 성취도를 통계 화면에서 보여 준다.

이 요구사항 목록이 그대로 데이터 액세스 문제의 목록이기도 하다.
카드 CRUD, 여러 건을 한 트랜잭션으로 묶는 CSV 가져오기, 조인이 필요한 "오늘 복습" 큐와 스마트 덱 조건 검색, 집계가 필요한 통계까지.
각 장에서 배우는 기술이 이 문제들을 하나씩 해결해 간다.

로컬에서 혼자 쓰는 앱으로 만들므로 로그인과 인증은 다루지 않는다.

=== 기술 스택

[cols="1,2"]
|===
|항목 |선택

|JDK
|JDK 25 (LTS)

|빌드 도구
|Gradle (멀티 프로젝트)

|데이터베이스
|H2 (파일 모드 + `AUTO_SERVER=TRUE`)

|웹 프레임워크
|Spring Boot 4.1, Spring Web MVC

|서버사이드 렌더링
|Thymeleaf

|데이터 액세스
|JDBC → Spring JDBC → Spring Data JDBC → Spring JDBC Plus
|===

데이터베이스로 H2를 고른 이유는 설치가 필요 없기 때문이다.
의존성 하나만 추가하면 애플리케이션 안에서 함께 실행되고, 파일 모드로 쓰면 데이터가 디스크에 남는다.
URL에 ``AUTO_SERVER=TRUE``를 붙이는 자동 혼합 모드(auto mixed mode)를 쓰면, 애플리케이션이 파일 DB를 연 상태에서도 H2 콘솔 같은 다른 프로세스가 같은 DB에 접속할 수 있다.
개발 중에 "앱을 띄워 둔 채 SQL을 직접 날려 보는" 작업 흐름이 가능해진다.

화면은 서버에서 HTML을 완성해 내려보내는 서버사이드 렌더링(SSR)으로 만든다.
템플릿 엔진은 Spring Boot가 공식 스타터로 지원하고 HTML 문서 그대로가 템플릿이 되는 Thymeleaf를 골랐다.
이 책의 주인공은 데이터 액세스 계층이므로, 화면 쪽은 최소한의 문법만 쓴다.

=== 저장소 구조와 실행 방법

책의 예제는 이 저장소의 `examples/` 디렉터리에 있고, 실제로 컴파일되고 테스트가 통과하는 코드다.
원고의 코드 조각은 이 소스 파일들을 그대로 참조해 실린다.

[listing]
----
examples/
├── ch01-jdbc-basics          # 1장: JDBC 표준 API
├── ch02-jdbc-template        # 2장: JdbcTemplate, NamedParameterJdbcTemplate
├── ch03-transaction-template # 3장: TransactionTemplate
├── ch04-transaction-aop      # 4장: @Transactional
├── ch05-boot-jdbc            # 5장: Spring Boot 웹 앱 (flashcard 기본판)
├── ch06-data-jdbc            # 6장: Spring Data JDBC
├── ch07-jdbc-plus            # 7장: Spring JDBC Plus (flashcard 완성판)
└── ch08-kotlin               # 8장: Kotlin 팁
----

JDK 25가 설치되어 있다면 각 장의 예제를 바로 실행할 수 있다.

[source,shell]
----
cd examples

# 장별 테스트 실행
./gradlew :ch01-jdbc-basics:test

# 콘솔 예제 실행 (1~4장, 8장)
./gradlew :ch01-jdbc-basics:run

# 웹 앱 실행 (5~7장)
./gradlew :ch07-jdbc-plus:bootRun

# 전체 빌드
./gradlew build
----

1~4장은 데이터 액세스 개념에 집중하는 콘솔·테스트 예제이므로, 카드와 덱 두 테이블만 있는 간결한 스키마를 쓴다.
5장에서 이 스키마 그대로 웹 앱을 만들고, 7장에서 복습 일정과 통계까지 담는 완성판 스키마로 확장한다.
