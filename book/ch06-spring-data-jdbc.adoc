== Spring Data JDBC: 리포지토리와 애그리거트

`insert into cards ...`, `select ... where id = :id`, `delete from ...`.
5장까지 우리가 쓴 SQL의 상당수는 어느 테이블에나 똑같이 생긴 기본 CRUD였다.
Spring Data JDBC는 이 뻔한 부분을 인터페이스 선언만으로 만들어 주면서도, JPA 같은 무거운 기계 장치(영속성 컨텍스트, 지연 로딩, 변경 감지)는 들이지 않는다.
"ORM의 편의 중 단순한 것만, Spring JDBC의 투명함은 그대로"가 이 기술의 설계 철학이다.

예제 모듈은 `examples/ch06-data-jdbc`, 의존성은 `spring-boot-starter-data-jdbc` 하나다.

=== 애그리거트: 함께 저장되고 함께 지워지는 단위

Spring Data JDBC의 중심 개념은 도메인 주도 설계(DDD)에서 온 *애그리거트*(aggregate)다.
"항상 함께 저장되고 함께 지워지는 객체 묶음"으로, 묶음의 대표를 애그리거트 루트라 한다.

=== 리포지토리: 선언이 곧 구현

리포지토리는 인터페이스 선언만으로 완성된다.

[source,java,indent=0]
----
include::{examples}/ch06-data-jdbc/src/main/java/flashcard/datajdbc/DeckRepository.java[tag=class]
----

``ListCrudRepository``를 상속하는 것만으로 `save`, `findById`, `findAll`, `deleteById` 등이 생긴다.
여기에 세 가지 방식의 조회가 공존한다.

1. *상속받은 CRUD*: 구현 없이 제공.
2. *메서드 이름 파생 쿼리*: ``findByNameContaining``처럼 이름 규칙으로 쿼리를 생성.
3. *`@Query`*: 복잡한 조회는 SQL을 직접. 2장에서 배운 이름 있는 파라미터가 그대로 쓰인다.

``findAllSummaries``처럼 엔티티가 아닌 record(`DeckSummary`)를 돌려주는 조회 전용 쿼리도 ``@Query``로 자연스럽게 처리된다.
"기본은 자동, 복잡한 것은 SQL"이라는 균형이 Spring Data JDBC를 쓰는 감각이다.

=== 함정: 식별자 인용과 H2

이 장의 엔티티에서 눈에 걸리는 부분이 있었을 것이다.

[source,java]
----
@Table("DECKS")
...
@MappedCollection(idColumn = "DECK_ID", keyColumn = "CARD_INDEX")
----

왜 대문자일까?
Spring Data JDBC는 SQL을 생성할 때 식별자를 따옴표로 감싼다(quoting).
따옴표로 감싼 식별자는 대소문자를 구별하는데, H2는 따옴표 없이 만든 테이블·컬럼 이름을 *대문자*로 저장한다.
즉 ``create table decks ...``로 만든 테이블의 실제 이름은 ``DECKS``이고, 애너테이션에 ``"decks"``라고 적으면 ``"decks"``라는 소문자 이름을 찾다가 실패한다.

클래스·필드 이름에서 *유도되는* 이름(`Deck` → `DECK`, `cardCount` → `CARD_COUNT`)은 프레임워크가 DB 관례에 맞춰 대문자로 만들어 주므로 문제가 없다.
문제는 애너테이션에 *직접 적은* 이름뿐이다. 그래서 직접 적을 때는 H2가 저장하는 형태인 대문자로 맞췄다.
PostgreSQL은 반대로 소문자로 저장하므로, DB를 옮길 때 이 지점이 흔한 이식성 함정이 된다.

=== 정리

기본 CRUD는 선언으로, 복잡한 조회는 여전히 SQL로.
Spring Data JDBC는 2장에서 익힌 Spring JDBC 위에 얇게 얹히는 기술이라, 아래층의 지식이 그대로 통한다.

다만 실무 규모의 앱을 만들다 보면 아쉬움이 생긴다.
``@Query``에 적는 SQL이 늘어날수록 컬럼 목록 나열이 반복되고, `save` 하나로 insert와 update를 겸하는 설계는 "새 객체인지 아닌지"를 프레임워크가 판단하게 만든다.
이 아쉬움을 노린 확장 라이브러리가 다음 장의 Spring JDBC Plus다.
그리고 다음 장에서 드디어 Flashcard를 요구사항 전부와 함께 완성한다.
