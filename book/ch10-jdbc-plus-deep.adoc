== Spring JDBC Plus 더 깊이: 휴지통부터 배치까지

7장에서는 Spring JDBC Plus의 뼈대인 3분할 구조(인터페이스, SQL 클래스, 구현)로 Flashcard를 완성했다.
이 장에서는 그때 쓰지 않고 지나간 Plus의 나머지 기능들을 살펴본다.
삭제를 되돌릴 수 있게 하는 soft delete, 애그리거트를 쿼리 한 번으로 읽는 조회, 대량 저장, 그리고 파라미터 처리의 소소하지만 실무적인 개선들이다.

예제 모듈은 ``examples/ch10-jdbc-plus-deep``로, 화면 없이 리포지토리와 테스트에 집중한다.
설정(표준 리포지토리를 끄고 Plus를 켜는 프로퍼티)은 7장과 같고, 의존성은 7장에서 웹 관련 스타터를 덜어 낸 최소 구성이다.

=== Soft delete: 삭제를 UPDATE로

사용자가 덱을 지웠다가 "아차" 하는 일은 반드시 생긴다.
행을 정말 지우는 대신 "지워졌음" 표시만 해 두면 복원이 가능해진다.
이른바 soft delete인데, 직접 구현하면 삭제 코드를 전부 UPDATE로 바꿔 써야 하는 성가신 패턴이다.
Plus는 이를 애너테이션 하나로 처리한다.

상태가 셋 이상인 모델(활성/보관/삭제)에 어울린다.

주의할 점이 하나 있다. 위 테스트에서 보듯 *조회는 자동으로 걸러 주지 않는다.*

=== 여기서 다루지 않은 것

Plus에는 이 밖에도 몇 가지가 더 있다.
커스텀 SQL에서 테이블 별칭을 제어하는 ``@SqlTableAlias``, 컬럼을 SQL 함수 표현식으로 읽는 ``@SqlFunction``, 그리고 `JdbcReactiveTemplate` 같은 리액티브 지원이다.
필요해졌을 때 공식 저장소(github.com/naver/spring-jdbc-plus)의 문서와 테스트 코드를 보면 이 장의 연장선에서 어렵지 않게 읽을 수 있을 것이다.

=== 정리

이 장의 기능들도 결국 7장의 철학을 반복한다.
자동화가 어울리는 곳(삭제 표시, 배치 파라미터, 조인 SQL 생성)은 자동화하되, SQL이 보여야 하는 곳에서는 SQL을 감추지 않는다.
soft delete가 조회 조건을 대신 걸어 주지 않는 것도, 애그리거트 조회가 결국 눈에 보이는 조인 SQL인 것도 같은 태도다.

=== 책을 마치며

JDBC 표준에서 출발해 템플릿, 트랜잭션 추상화, 자동 설정, 리포지토리, 확장 라이브러리, 다른 언어, 그리고 그 심화까지 올라왔다.
층이 올라갈수록 코드는 줄었지만, 밑층이 사라진 적은 한 번도 없었다.
어떤 프레임워크를 쓰든 결국 SQL이 커넥션을 타고 흐른다는 사실을 기억하는 한, 어느 층에서 문제가 생겨도 내려가 볼 수 있다.
그 감각이 이 책이 남기고 싶은 전부다.
