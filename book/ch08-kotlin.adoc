== Kotlin 프로젝트 팁

마지막 장은 보너스다.
Spring JDBC 생태계를 Kotlin 프로젝트에서 쓸 때 도움이 되는 문법과 관례를 모았다.
Spring Framework는 Kotlin을 공식 지원하며, 이 책에서 배운 모든 층이 Kotlin에서 그대로 동작한다.

예제 모듈은 `examples/ch08-kotlin`이다.

* `kotlin-reflect`: `DataClassRowMapper`와 `BeanPropertySqlParameterSource`가 Kotlin 클래스의 생성자·프로퍼티를 들여다볼 때 필요하다.
* `org.jetbrains.kotlin.plugin.spring`: Kotlin 클래스는 기본이 `final`이라 4장에서 배운 상속 기반 프록시를 만들 수 없다. 이 플러그인이 `@Service`, `@Transactional` 등이 붙은 클래스를 자동으로 `open`으로 바꿔 `@Transactional`이 정상 동작하게 한다. Kotlin + Spring 프로젝트의 사실상 필수 플러그인이다.

=== 생태계 참고 사항

* *Spring Data JDBC와 data class*: 6장의 엔티티도 data class로 쓸 수 있다. `val` 프로퍼티와 `copy` 기반의 불변 모델이 Spring Data JDBC의 "저장 시점 상태 반영" 철학과 잘 맞는다.
* *Spring JDBC Plus*: Kotlin을 공식 지원하며, `spring-data-jdbc-plus-sql-kotlin` 모듈이 Kotlin DSL을 제공한다. 7장의 SQL 클래스와 리포지토리 구현 패턴도 Kotlin에서 동일하게 쓸 수 있다.
* *coroutine*: 이 책의 범위 밖이지만, JDBC는 블로킹 API이므로 coroutine에서 쓸 때는 `Dispatchers.IO`로 감싸는 것이 관례다.

=== 책을 마치며

JDBC 표준에서 출발해 템플릿, 트랜잭션 추상화, 자동 설정, 리포지토리, 확장 라이브러리, 그리고 다른 언어까지 올라왔다.
층이 올라갈수록 코드는 줄었지만, 밑층이 사라진 적은 한 번도 없었다.
어떤 프레임워크를 쓰든 결국 SQL이 커넥션을 타고 흐른다는 사실을 기억하는 한, 어느 층에서 문제가 생겨도 내려가 볼 수 있다.
그 감각이 이 책이 남기고 싶은 전부다.
